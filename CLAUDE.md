# RAW by aurare (anciennement Rollout, et TkTgen avant) : contexte du projet

Réponds en français. Andy (Angers) construit RAW by aurare (« RAW », une app du studio Aurare) avec un ami : une web app pour artistes musicaux qui crée des carrousels TikTok (hooks, paroles, photos Drive) et un studio vidéo (prise caméra synchronisée sur l'audio officiel, paroles incrustées). En ligne : https://raw.aurare.app (Vercel ; l'ancienne adresse getrollout.netlify.app sur Netlify)

## Liste des fonctionnalités
- `FONCTIONNALITES.md` : tout ce que fait l'app, du point de vue de l'artiste, par rubrique, avec son état (En ligne, En test, À venir, En attente). À mettre à jour à chaque fonctionnalité ajoutée, changée ou retirée (dans le même commit). Sert aussi pour la home.

## Stack
- Next.js 15 (App Router), TypeScript 5 (ne pas passer à 7 ; pas de `baseUrl` dans tsconfig), Auth.js (next-auth beta) avec login Google + `drive.file` seul (plus de `drive.readonly`, permission restreinte : l'app ne voit que ce qu'elle a créé ; tout s'importe depuis l'appareil). Session JWT d'un an, renouvelée à chaque visite.
- Données : Neon Postgres (table `workspaces`, un JSON par email, compare-and-swap sur `rev`). Sans `DATABASE_URL`, repli sur `.data/workspaces.json` (badge « Local file »). Plusieurs appareils : l'app vérifie la révision (`GET /api/workspace?rev=N` → `{ unchanged }` si rien n'a bougé, `workspaceRev` : quelques octets lus dans Neon) au retour sur la page et toutes les 30 s, et ne relit les données que si elles ont changé (les relire à chaque fois avait usé 4 Go du transfert mensuel de Neon) (si rien n'attend d'être enregistré), et un conflit d'enregistrement est fusionné (`lib/merge.ts`, fusion à trois sur la dernière version chargée / enregistrée).
- Nom : « RAW by aurare » (onglet, manifeste, pages légales), « RAW » seul dans les phrases et l'icône installée ; logo `components/Wordmark.tsx` (le RAW dessiné par Andy, nov. 2026, + « by aurare » en minuscules, blanc, en exposant, Space Grotesk 400, masqué sur téléphone) ; icône = ce RAW centré dans un carré noir (`app/icon.svg`, 78 % de la largeur ; `public/brand/raw-*` ; PNG Apple 180 et Android 192 / 512 dans `public/`, les « maskable » à 58 % pour rester dans la zone sûre). Les noms internes « rollout » (caches des modèles `rollout-align`…, événements `rollout:…`, clés localStorage) restent : les changer ferait retélécharger les modèles et perdre des réglages.
- Déploiement : GitHub + Vercel (raw.aurare.app, variables d'environnement dans Vercel, `DATABASE_URL` = Neon). Avant : Netlify (`netlify.toml`, gardé, ignoré par Vercel ; minutes de build épuisées en novembre 2026). Ne jamais coder le domaine en dur (origine déduite par requête, `AUTH_URL` dans Vercel).
- Mode démo : `/studio?demo` (connecté) ouvre un compte vierge en mémoire seulement (`lib/demo.ts`) : rien n'est enregistré sur le serveur ni écrit sur le Drive, recharger repart de zéro.
- Tests : `npm test` (vitest, fichiers dans `tests/`). Typecheck : `npm run typecheck`.
- Ne jamais lire ni afficher `.env.local`.

## Architecture utile
- Trois espaces dans les deux studios : **Bibliothèque** (colonne de gauche / onglet du milieu sur mobile : la release — paroles, et pour la vidéo audio + prises — puis les listes de textes partagées, et les photos pour le carrousel), **Création** (board central), **Style** (colonne de droite ; le Cadrage vidéo y est). Les morceaux partagés (`lyricsRow`, `textGroup`) sont construits dans `Studio.tsx` et passés à `VideoStudio`. Sauvegarde avant cette refonte : tag `ui-before-library`.
- `components/Studio.tsx` : carrousel + coquille de l'app (header, release, overlays). `components/VideoStudio.tsx` : studio vidéo, gardé monté (caché) quand on passe au carrousel. `components/SlideCard.tsx` : carte de slide (sources, thème, sections de paroles). `components/Inspector.tsx` : réglages de la slide. `components/CaptionStyle.tsx` : style des paroles / hooks vidéo.
- `components/ui.tsx` : Modal, Menu (option `float` pour sortir d'une colonne), Section (panneaux repliables, fermés par défaut), **Select** (menu déroulant maison : ne jamais utiliser de `<select>` natif).
- `lib/render.ts` : rendu canvas (`drawStyledText` : dessiné par calques sur toutes les lignes, `paintAll` — tous les fonds, puis tous les contours, puis toutes les lettres : le fond d'une ligne ne cache plus les lettres de celle d'au-dessus). `lib/types.ts` : modèle de données.
- Médias (audio, vidéo, polices, LUT) : IndexedDB local (`lib/idb.ts`), jamais envoyés au serveur (sauf copie Drive voulue).
- Dossier de l'app en double à la racine du Drive (deux appareils ou adresses, la recherche de Drive qui ne voyait pas encore le premier) : `findDriveTwins` fusionne les autres dossiers « RAW by aurare » (casse ignorée, ou Rollout / TkTgen) dans celui de l'appareil (`mergeFolders`, puis les fichiers en double à la corbeille) ; `findOrMakeFolder` prend toujours le plus ancien (`orderBy: createdTime`) et recherche une seconde fois après 2,5 s avant d'en créer un ; clé `tktgen-drive-twins-v2` (refait une fois).
- Doublons Drive : `uploadToDrive` réutilise le fichier identique du dossier (MD5, ou nom + taille au-delà de 160 Mo) ; `findDriveTwins` (une fois par jour, `tidyTwins` dans `Studio.tsx`) fusionne les dossiers jumeaux et met à la corbeille les fichiers en double.
- Photos en double dans une liste (même image, fichiers différents) : empreinte visuelle `PicRef.hash` (`lib/imageHash.ts`, 17 × 16 = 256 bits, même photo à ≤ 12 bits) ; calculée à l'ajout (`uploadToList` n'ajoute pas une photo déjà là) et, pour les anciennes, à l'ouverture de la liste (sans étape d'annulation) ; « Retirer les doublons » dans l'éditeur (`dropRepeats`, le fichier Drive à la corbeille s'il ne sert plus).
- Arborescence Drive (`lib/drive.ts`, `DRIVE_PATHS`, `driveFolder`) : `RAW by aurare / Photos / <liste>`, `RAW by aurare / Releases / <release> / Audios, Videos`, `RAW by aurare / Utils / LUTS, Fonts` (dossier `APP_FOLDER` ; un ancien dossier « Rollout » ou « TkTgen » est renommé à la première visite, `OLD_FOLDERS`), créée à la connexion (`ensureDriveTree`) ; chaque envoi va dans son dossier ; une liste de photos ou une release crée son dossier et le renomme avec elle (`renameDriveFolder`) ; les listes de photos se remplissent par glisser-déposer / « Ajouter des photos » (plus de dossiers liés ni d'import depuis le Drive) ; les anciens fichiers à plat dans Rollout sont rangés une fois par appareil (`tidyDriveRoot`). Sauvegarde avant : tag `ui-before-drive-tree`.
- Vidéos et versions : une vidéo = le fichier caméra et ce qui en dépend (synchro, prises, profil caméra de l'étalonnage, objectif anamorphique `desqueeze` : `desqueeze()` dans `lib/videoSource.ts` élargit l'image dans `drawScene`, `cropFor` découpe en pixels caméra) ; une version (`VERSION_KEYS`, « Dupliquer cette version ») garde tous les choix du post (segment, textes, styles, cadrage, format, étalonnage ; les anciennes sans `all` reprennent cadrage / format / étalonnage de la vidéo). « + » = nouvelle vidéo de zéro (`addVideo` : le même morceau / version d'audio, les paroles de la release, le look des paroles, le format et le segment ; ni fichier, ni prises, ni hooks, ni vidéos par-dessus, ni étalonnage), numérotée parmi les vidéos de la release seulement (`nextClipName` sur `projects` : les prises importées, rangées comme des vidéos, la faisaient passer à « Vidéo 7 ») ; « Dupliquer » (menu « … ») = même fichier, lu via `media` (jamais recopié sur l'appareil), sans la copie Drive ; on n'efface un fichier local ou une copie Drive que si aucune autre vidéo ne s'en sert.
- Bandes noires (masque à un format, comme DaVinci) : `drawMatte` / `MATTES` dans `lib/render.ts`, `MatteSelect` dans `ui.tsx` ; `SlideCfg.matte` (à la slide, pas à la photo : une autre photo les garde ; copié par « Appliquer à toutes les slides ») et `VideoSettings.matte` (choix de la version)  ; au-dessus de l’image, sous les textes, à l’aperçu comme à l’export ; avec des bandes, l’image n’a qu’à couvrir la partie visible entre elles (`clampPic` lit `pic.matte`, passé au dessin et au glisser, jamais gardé dans la photo).
- Plusieurs carrousels par release : `lib/carousels.ts` (le carrousel ouvert vit dans les champs du projet, les autres dans `project.carousels`).
- Calage des paroles : toute la chaîne (alignement forcé puis relais) est dans `lib/lyricsPipeline.ts` (`placeByAlignment`), utilisée par `VideoStudio` ET par la page de test `/dev/lyrics` (dev seulement, 404 en production : un fichier audio + des paroles, le code exact de l'app, résultat dans `window.__lyricsResult`) ; la piloter dans Chrome (Playwright, profil persistant pour garder les modèles en cache) pour mesurer ce que fait vraiment l'app : mes bancs Node/ffmpeg donnaient des résultats différents de l'app. Le relais compare 4 écoutes (fenêtre décalée, avec/sans contexte) et garde la plus complète (`usefulFor`, `hitsOf` : mots des lignes à placer, boucles et mots empilés retirés) ; le contexte = les 2 dernières lignes ENTIÈRES ponctuées (`contextBefore` : une ligne coupée faisait boucler Whisper) ; résultat appliqué seulement s'il ne tasse pas plus de lignes (`packedLines`) ; puis `afterBreaks` : une ligne mal entendue qui démarre juste avant une coupure de la prod (silence −50 dB ≥ 60 ms, `silencesOf`) démarre après ; puis `spreadPacked` : des lignes mal entendues empilées (débuts < 0,6 s d'écart) suivies de ≥ 1,5 s libres se partagent ce temps par lettres (avec la ligne d'avant si elle fait partie du tas). Refrains répétés : chaque bloc répété du texte est traité (`findRepeats` : un refrain en intro et le même à la fin = deux blocs) ; la période se mesure sur tout l'espace libre entre la ligne d'avant et celle d'après (`repeatPeriodIn` : le meilleur passage de (copies − 1) périodes, le double et la moitié ne sont pas rivaux ; la moyenne sur toute la fenêtre ne trouvait rien quand le bloc était mal placé, une intro floue) ; un bloc sans période nette prend celle du même texte ailleurs ; le départ est cherché dans tout cet espace (`placeCopies`), une copie commence et finit dans un souffle (première lettre ≥ 0,16 s, dernière ≤ fin − 0,1 s : le refrain de WANNA TRY finit une copie et commence la suivante sur la même ligne) et la dernière peut dépasser la fin du fichier (du silence) ; un départ décalé d'une période colle presque aussi bien aux lettres (une copie posée sur la musique de l'intro) : des deux, on garde celui dont toutes les copies se ressemblent (la moins semblable aux autres, log-mel, `copiesAlike` dans `placeCopies`, nettement plus semblable : WANNA TRY 0,53 contre 0,33 ; la voix vue par le modèle ne départageait pas, refrain noyé) ; sans ça WANNA TRY donnait 12,70 s au lieu de 16,76 selon un écart infime du modèle. Mesuré sur WANNA TRY [MASTER INSTA] avec le refrain écrit en intro : intro 16,4 s (voix isolée 16,5 s), refrain final aux temps de la V4 ; V4, Fontaines, Ally, Dakeez, Smeels, Sombr, Temper : 0,00 s d'écart avant / après. Enfin `applyRepeat` (`lib/repeatBlocks.ts`) : un groupe de lignes répété mot pour mot ≥ 3 fois de suite (`findRepeat`), mal entendu (moyenne `LyricWord.conf` < 0,15), dont le son se répète avec une période nette (`melFrames` + `repeatPeriod`, log-mel 40 bandes, ressemblance ≥ 0,5 : refrain de WANNA TRY 0,60 à 4,06 s ; Fontaines D.C. 0,41 écarté) : les copies sont « écoutées ensemble » (émissions moyennées à une période d'écart, `foldedFit`, chaque début possible essayé) et chaque copie placée pareil. Ces règles ne dépendent pas de Whisper : le relais répond différemment selon le navigateur / la carte graphique (le hook de WANNA TRY était juste chez Andy avec 694737a, faux dans Chrome headless), ne jamais compter sur lui seul. Détails :
- Calage des paroles par alignement forcé (sauvegarde avant : tag `before-forced-align`) : `public/align/worker.js` (MMS-300M forced aligner, CC-BY-NC-4.0, onnxruntime-web 1.20.1 : sur carte graphique le modèle fp32 de onnx-community, 1,26 Go, cache `rollout-align-fp32` ; sur processeur (wasm) le fp16 de tatsu020, 630 Mo, cache `rollout-align`, ~2 min pour 80 s d'audio. Ne JAMAIS passer le fp16 sur WebGPU : il y donne des valeurs fausses sur certains morceaux (mesuré dans Chrome contre la référence processeur) ; l'int8 et le q4 ne marchent pas ou sont trop lents en wasm ; extraits de 30 s avec 2 s de contexte, log-probabilités par image de 20 ms) → `lib/alignAI.ts` (`alignEmissions`, garde la dernière chanson en mémoire) → `lib/forcedAlign.ts` (`alignWordsForced` : chemin CTC de Viterbi sur les lettres a-z + apostrophe, `faNorm`, ~50 ms ; les mots d'une ligne éloignés de plus de 4 s du reste sont recalés près d'elle, `strayBounds` ; `LyricWord.doubt` = ligne douteuse (éparpillée, ou tassée au-delà de 26 lettres/s jusqu'à la ligne suivante : seuil mesuré sur 3 chansons, la confiance des lettres ne discrimine pas), point jaune `.cue-doubt` dans les lignes de paroles, ôté quand la ligne est retouchée `manual` ; `LyricWord.exact` : ne PAS passer ces mots par `tightenLineStarts` / `snapLines` dans `placeWords` (ça reculait une ligne de 1,1 s) ; le dernier mot d'une ligne dure au plus 1 s (`HOLD`) ; un blanc à l'intérieur d'une ligne coûte `FA_TUNE.lineBlank` = 0,05 ; paroles françaises (`looksFrench`) alignées sur une graphie phonétique (`frenchSound` : « en » → « an », finales muettes ôtées, « est » → « e » : le modèle écrit ce qu'il entend, « comprends » = « compran ») et lettres de début de ligne jamais entendues (< 3 %, une syllabe avalée : « Qu'est-ce qui » chanté « s'qui ») recollées devant la première entendue (`startOnHeard`). Relais (`lib/lyricsRelay.ts`, `relayWeakLines`) : un passage presque muet pour l'alignement (lignes `weak` : moyenne de leurs lettres < 0,3 sur un passage dont la moyenne < 0,12, dont certaines `doubt`, tassées ; un hook ou un refrain noyé dans les effets) est réécouté par Whisper en mode phrase (`transcribe(…, { mode: "segment", raw: true })`) ; les lignes du passage sont alignées (`alignSong`) sur les mots de ces phrases (une phrase peut porter plusieurs lignes : un bloc de refrain) ; une ligne non tassée garde son heure si l'écart ≤ 1 s ; une ligne avec une lettre nettement entendue (> 0,6) n'est jamais `weak`. Whisper reçoit en amorce les lignes chantées juste avant (`prompt` → `decoder_input_ids` = <|startofprev|> texte <|startoftranscript|><|fr|><|transcribe|>, écho retiré de la 1re phrase) : sans elle il rendait « ... » / « Sous-titrage » sur presque toutes les fenêtres du hook de WANNA TRY (une seconde de décalage suffisait à basculer) ; amorcer avec TOUTES les paroles le fait recopier et boucler. Fenêtre sans parole (`noSpeech`) : réessayée décalée. Le relais écoute en mode mot ET phrase (amorcés) : les mots (plus fins, `withoutLost` retire ceux empilés au même instant) là où il y en a, les mots des phrases ailleurs (`mergeHeard` : le mode mot s'arrête parfois au 1er bloc d'un refrain) ; un 1er mot de ligne qui dure > 0,6 s jusqu'au suivant a absorbé le blanc avant lui (coupure dans la prod) : recalé 0,25 s avant le mot suivant (`FIRST_LONG`). Essais écartés (mesurés) : répartir les lignes non entendues sans Whisper (Ally Bakst 0,11 → 5 s), zones de surdité ≥ 4 s, seuil par ligne seul (le rap rapide est à moitié entendu, DAKEEZ 85 → 72 %). Mesurer TOUJOURS avec l'audio préparé comme l'app (décodé par le navigateur, OfflineAudioContext 16 kHz) : ffmpeg donnait d'autres émissions et un réglage qui ne tenait pas dans l'app ; une coupure de ligne qui ne suit pas le chant (« …partir dans / tes draps ») fait commencer la ligne sur le mot chanté avant, ce n'est pas une erreur, jamais dans la ligne suivante ; vérité terrain de WANNA TRY V4 mesurée sur l'acapella : attaques de voix à 35,25 / 38,5 / 42,5 / 46,75 s, Whisper y donnait 36,5 / 40,8… à tort) ; les mots posés deviennent `project.heardWords`, donc la resynchro au changement de texte, les versions audio et les retouches marchent comme avant. Utilisé quand les paroles sont écrites (`src` « song » / « all ») ; sinon, ou en cas d'échec, Whisper (voir ci-dessous). Mesuré hors app contre LRCLIB sur 6 chansons FR/EN : médiane 0,05–0,46 s, refrains serrés (« Air, air », « Non ×4 ») encore fragiles. Whisper : si les temps par mot s'effondrent (tous au même instant : `lostCount`), la fenêtre est réécoutée en temps par phrase (`wordsFromSegments`, mode `segment` du worker), `respreadLost`, et `dropLoops` garde une répétition présente dans les paroles écrites.
- Piste vidéo sans multicam (`videoTrackEl`, rendue par `camsEl` quand aucune caméra 2-4) : le fichier caméra en clip ; non `linked`, glisser = `offset`, bords = `VideoSettings.clipIn` / `clipOut` (secondes dans le fichier, dans `VERSION_KEYS`, `clipSpan`) ; hors de ce passage l'image est noire (`pictureOf`, `inside` de l'export) ; la bande violette de la forme d'onde et l'aimant du segment suivent le passage rogné. Le bandeau coloré de la forme d'onde (vidéo réglée, `bandOf`) porte l'icône film et « VIDÉO n » (`FILM_PATH`). Son de la prise : `VideoSettings.clipVolume` (0-1, aucun = coupé) ; à la lecture le lecteur caméra n'est plus muet sur le passage gardé ; à l'export `withCameraSound` mêle le son de la caméra (lu par `readSound`, gardé par fichier) au son officiel dans un `OfflineAudioContext`. Le clip n'a pas de `data-a` : il n'est pas collant comme les autres clips.
- Plusieurs vidéos par-dessus (sauvegarde avant : tag `before-multi-overlay`) : `VideoSettings.overlays` (de bas en haut, un ancien `overlay` seul lu comme une, plus jamais écrit : `overlaysOf`, `overlayOf(s, id)`, `withOverlays`, `patchOverlay`), 4 vidéos au plus dans un projet (`videosIn`) ; numéros après les caméras, de bas en haut (`overNo(s, id)`) ; une ligne par vidéo par-dessus (`overlayTrackEl(o)`, `data-ov`), dessinées dans l'ordre (`overlayPictures`, `drawScene(…, overs)`, `overlayBoxes` : la plus haute attrapée d'abord), son et export pour chacune ; prise importée = sur sa propre ligne, en haut (`importTakes`, recalée à sa synchro) ; « Ajouter au projet » / glisser depuis la bibliothèque au-dessus de la ligne de base = sa ligne, sur la ligne de base = multicam ; menu ⋯ d'une prise : sur sa ligne → « Mettre dans le multicam », caméra → « Mettre sur sa propre piste », et « Retirer du projet » ; glisser vertical sur N lignes (`videoRows`, `landing` : base ↔ une par-dessus = échange `swapBase` ou multicam, deux par-dessus = ordre `order` (insertion : la vidéo prend la ligne visée, celles d'entre les deux se décalent d'une ligne, à l'aperçu du glisser comme au lâcher ; plus un échange de deux), un plan du multicam vers le haut = sa ligne) ; la colonne de droite règle celle cliquée (`overLook` = son id).
- Vidéo par-dessus / incrustation (sauvegarde avant : tag `before-overlay-video`) : `VideoSettings.overlay` (`VideoOverlay` : prise `clip`, `offset` sur la piste officielle, `clipIn`/`clipOut`, centre `x`/`y` %, largeur `w` %, `radius`, `volume` ; dans `VERSION_KEYS`) ; jamais une caméra du projet (`overlayOf`) ; lue comme une caméra multicam (ajoutée à `angleClips`, lecteur caché, sa LUT 33) ; `syncAngles` la fait jouer sur son passage avec son son ; `overlayPicture` (aperçu) / `overAt` (export, `VideoSource` dans l'ordre) → `drawScene(…, over)` la dessine entière, étalonnée par le `Grader` partagé, coins arrondis, sous les bandes et les textes (`overlayBox` pour la glisser / la molette) ; son mêlé à l'export par `withCameraSound` ; piste `overlayTrackEl` (glisser, rogner, réglages, retirer) ; copie Drive avec son `offset` (`makeCopy({ off })`). Cliquée (aperçu, piste), `overLook` : la colonne de droite règle sa prise (`camTake` = `ovTake`), son cadrage est dessiné dans son cadre (`drawFramed` dans la boîte). Geste CapCut : un plan de la piste multicam tiré vers le haut (`liftRef`, capture sur la piste) passe par-dessus ; le clip par-dessus tiré vers le bas revient en caméra. Bandes noires et zoom progressif propres à chaque caméra : `matte` / `push` / `pushIn` de la prise (`AngleLook`, `ownOr` : sinon ceux du projet ; 0 / false = aucun), écrits par `writeLook`.
- Bloc vidéo de la timeline (`.video-block` : `overlayTrackEl` puis `camsEl("track")`, les boutons multicam `camsEl("controls")` dessous) ; glisser-déposer HTML5 d'une prise de la bibliothèque, seulement une prise pas encore dans le projet (`takeDrag` : celles du projet sont déjà sur la timeline, leur ligne se clique seulement ; `blockDrop`, `rowOf` : au-dessus de la ligne de base = par-dessus à `dropAt`, sinon caméra) ; « Synchroniser » = `autoSync` puis `syncOthers` (caméras + par-dessus via `resyncTake`, `null` = pas de correspondance : reste libre), toujours toutes, même si la base échoue ; prise synchronisée = `linked` (verrouillée comme la base : elle le reste en devenant la base ; venant de par-dessus, seulement si elle est encore à sa place synchronisée) ; première synchro réussie = son de la vidéo coupé (`clipVolume` / `overlay.volume` effacés, seulement si `score` était vide) ; un seul message par `tellSync` (calées / libres, l'erreur seulement si aucune n'est calée). Taille et place par-dessus = celles de la vidéo (`VideoSettings.box`, recopiées depuis `overlay` par un effet, dans `CAM_KEYS`, `boxOr`) : elles suivent la vidéo dans un échange ; une vidéo qui n'a été que celle du dessous, passée au-dessus, garde l'image entière (`full` : dessinée comme la vidéo du dessous, son cadrage tel quel, `boxOr(b, true)`), jamais la petite boîte d'une vidéo ajoutée ; la déplacer ou la redimensionner à la main en fait une boîte (`patchOverlay`). Échanger deux plans ne change que leur ordre. L'échange ne relit que le fichier caméra (`loadedFor` : même projet et vidéo, l'audio et la forme d'onde restent).
