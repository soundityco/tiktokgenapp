# Rollout (anciennement TkTgen) : contexte du projet

Réponds en français. Andy (Angers) construit Rollout avec un ami : une web app pour artistes musicaux qui crée des carrousels TikTok (hooks, paroles, photos Drive) et un studio vidéo (prise caméra synchronisée sur l'audio officiel, paroles incrustées). En ligne : https://getrollout.netlify.app

## Stack
- Next.js 15 (App Router), TypeScript 5 (ne pas passer à 7 ; pas de `baseUrl` dans tsconfig), Auth.js (next-auth beta) avec login Google + `drive.file` seul (plus de `drive.readonly`, permission restreinte : l'app ne voit que ce qu'elle a créé ; tout s'importe depuis l'appareil). Session JWT d'un an, renouvelée à chaque visite.
- Données : Neon Postgres (table `workspaces`, un JSON par email, compare-and-swap sur `rev`). Sans `DATABASE_URL`, repli sur `.data/workspaces.json` (badge « Local file »). Plusieurs appareils : l'app relit les données au retour sur la page et toutes les 30 s (si rien n'attend d'être enregistré), et un conflit d'enregistrement est fusionné (`lib/merge.ts`, fusion à trois sur la dernière version chargée / enregistrée).
- Déploiement : GitHub + Netlify (`@netlify/plugin-nextjs`, `publish = ".next"` dans netlify.toml, ne pas définir de Base directory). Ne jamais coder le domaine en dur (origine déduite par requête, AUTH_URL dans Netlify).
- Mode démo : `/studio?demo` (connecté) ouvre un compte vierge en mémoire seulement (`lib/demo.ts`) : rien n'est enregistré sur le serveur ni écrit sur le Drive, recharger repart de zéro.
- Tests : `npm test` (vitest, fichiers dans `tests/`). Typecheck : `npm run typecheck`.
- Ne jamais lire ni afficher `.env.local`.

## Architecture utile
- Trois espaces dans les deux studios : **Bibliothèque** (colonne de gauche / onglet du milieu sur mobile : la release — paroles, et pour la vidéo audio + prises — puis les listes de textes partagées, et les photos pour le carrousel), **Création** (board central), **Style** (colonne de droite ; le Cadrage vidéo y est). Les morceaux partagés (`lyricsRow`, `textGroup`) sont construits dans `Studio.tsx` et passés à `VideoStudio`. Sauvegarde avant cette refonte : tag `ui-before-library`.
- `components/Studio.tsx` : carrousel + coquille de l'app (header, release, overlays). `components/VideoStudio.tsx` : studio vidéo, gardé monté (caché) quand on passe au carrousel. `components/SlideCard.tsx` : carte de slide (sources, thème, sections de paroles). `components/Inspector.tsx` : réglages de la slide. `components/CaptionStyle.tsx` : style des paroles / hooks vidéo.
- `components/ui.tsx` : Modal, Menu (option `float` pour sortir d'une colonne), Section (panneaux repliables, fermés par défaut), **Select** (menu déroulant maison : ne jamais utiliser de `<select>` natif).
- `lib/render.ts` : rendu canvas (`drawStyledText`). `lib/types.ts` : modèle de données.
- Médias (audio, vidéo, polices, LUT) : IndexedDB local (`lib/idb.ts`), jamais envoyés au serveur (sauf copie Drive voulue).
- Doublons Drive : `uploadToDrive` réutilise le fichier identique du dossier (MD5, ou nom + taille au-delà de 160 Mo) ; `findDriveTwins` (une fois par jour, `tidyTwins` dans `Studio.tsx`) fusionne les dossiers jumeaux et met à la corbeille les fichiers en double.
- Arborescence Drive (`lib/drive.ts`, `DRIVE_PATHS`, `driveFolder`) : `Rollout / Photos / <liste>`, `Rollout / Releases / <release> / Audios, Videos`, `Rollout / Utils / LUTS, Fonts`, créée à la connexion (`ensureDriveTree`) ; chaque envoi va dans son dossier ; une liste de photos ou une release crée son dossier et le renomme avec elle (`renameDriveFolder`) ; les listes de photos se remplissent par glisser-déposer / « Ajouter des photos » (plus de dossiers liés ni d'import depuis le Drive) ; les anciens fichiers à plat dans Rollout sont rangés une fois par appareil (`tidyDriveRoot`). Sauvegarde avant : tag `ui-before-drive-tree`.
- Vidéos et versions : une vidéo = le fichier caméra et ce qui en dépend (synchro, prises, profil caméra de l'étalonnage, objectif anamorphique `desqueeze` : `desqueeze()` dans `lib/videoSource.ts` élargit l'image dans `drawScene`, `cropFor` découpe en pixels caméra) ; une version (`VERSION_KEYS`, « Dupliquer cette version ») garde tous les choix du post (segment, textes, styles, cadrage, format, étalonnage ; les anciennes sans `all` reprennent cadrage / format / étalonnage de la vidéo). « + » = nouvelle vidéo, mêmes réglages, autre fichier ; « Dupliquer » (menu « … ») = même fichier, lu via `media` (jamais recopié sur l'appareil), sans la copie Drive ; on n'efface un fichier local ou une copie Drive que si aucune autre vidéo ne s'en sert.
- Plusieurs carrousels par release : `lib/carousels.ts` (le carrousel ouvert vit dans les champs du projet, les autres dans `project.carousels`).
- Paroles : un seul texte par release, les sections `project.lyrics` (`lib/lyricsSections.ts` : découpage d'une chanson, slides en paroles, lien avec la vidéo via `songOf`/`lyricsLinked`, migrations au chargement). Éditeur unique `components/LyricsEditor.tsx` (tuile Paroles en tête de la Bibliothèque des deux studios, couleur or ; l'audio en vert, la vidéo en violet). Une slide retouchée à la main (`edited`) ne suit plus les sections.
- Copie de travail des prises (autres appareils) : après la synchro, d'abord `fastWorkCopy` (`lib/fastCopy.ts`, puce vidéo via WebCodecs : H.264 en 8 bits, HEVC Main 10 ou VP9 profil 2 en 10 bits, son lu par ffmpeg), sinon `makeWorkCopy` (`lib/convert.ts`, moteur ffmpeg à part) encode le passage ±2 s en gardant le minutage de l'original (image figée avant, son caméra), 10 bits 4:2:2/4:2:0 pour log/HDR/10 bits/ProRes, 8 bits pour le SDR, ≤ 1920 px ; envoyée sur le Drive (`drive.copy`). Sans le fichier caméra, l'app ouvre la copie (`copy:<clip>` en local, pastille « Copie Drive ») ; l'appareil qui a l'original exporte depuis l'original.
- Export vidéo étalonné (log / LUT) : d'abord `gpuGradedSource` (`lib/grade10.ts` : images décodées par WebCodecs en logiciel, plans Y/Cb/Cr 10 bits lus avec `copyTo`, BT.709 + LUT 65 tétraédrique dans un shader WebGL 2, comme ffmpeg), sinon `convertSegment` ffmpeg. Les images matérielles sans format lisible (HEVC sur Chrome Mac ou Android, la copie Drive sur téléphone) sont déposées sur le GPU par le navigateur (`drawRGB` : RGBA16F si possible, sinon 8 bits) puis étalonnées par la même LUT ; ffmpeg seulement si ça échoue aussi. Sauvegarde avant : tag `export-before-gpu-grade`.
- Synchro audio caméra ↔ officiel : `lib/syncAudio.ts` (le score = certitude de la position : extraits d'accord + écart avec les autres endroits ; la ressemblance du son ne compte qu'au-dessus d'un seuil bas, pour une voix seule au casque). Son de la caméra : décodé par le navigateur jusqu'à 400 Mo, sinon ffmpeg (piste son seule, secondes), en dernier recours capture en temps réel. Pendant la lecture, la copie de travail (puce vidéo) attend ; sa progression ne redessine le studio qu'à chaque pour cent ; le MD5 d'un envoi Drive se calcule par tranches (`md5Blob`). Paroles calées sur l'audio : `public/asr/worker.js` (Whisper via transformers.js 3.7.6 sur jsDelivr) → `lib/transcribe.ts` → `lib/lyricsAlign.ts`. Les mots sont dans `project.lyricWords` (temps absolus, `manual` = retouche gardée au recalage).
- Tags des textes (plusieurs par texte) : `TextPool.tags` (posés à la main), sinon le thème trouvé sert de tag (`poolTags`, `tagGroups`, `taggedItems` dans `lib/generate.ts`) ; une slide (`textSource.tags`) ou les hooks vidéo (`hookTags`) tirent dans les tags cochés (un texte qui en a au moins un). Vue « Par tag » de l'éditeur de liste (ouverte après un import). Les anciens `theme` / `hookTheme` valent un tag. Un tag peut aussi être exclu (« − » au survol de sa pastille, `TagChip` dans `ui.tsx`) : `textSource.notTags` / `VideoHook.notTags`, jamais tirés ni proposés (`drawableItems`, `taggedItems(…, not)`, `drawHook(…, not)`). Textes retouchés : après un export (carrousel ou vidéo), `VariantsDialog` propose de garder les textes tirés d'une liste puis modifiés (`lib/variants.ts` : `GenSlide.from`, `VideoHook.link`), ajoutés à leur liste avec les tags de la ligne d'origine ; une seule demande par texte (`Project.variantsAsked`).
- IA photo (test, sauvegarde avant : tag `before-ai-photo`) : « Plus net » (Swin2SR real-world ×4, 54 Mo, en tuiles de 160 px dont seul le centre est gardé ; pas le pipeline transformers.js, qui décalait et recadrait) et « Remplir le cadre » (LaMa 512, 208 Mo) ; onnxruntime-web, modèles gardés dans le Cache API, carte graphique sinon processeur (repli automatique si une opération échoue) ; la progression remplit le bouton, bouton IA rond (dégradé de Générer) en haut à droite de la slide, au survol, qui ouvre un menu des deux options (chacune dit ce qu’elle fait, ou pourquoi elle est grisée), anneau de progression ; `lib/photoAI.ts` + `public/photoai/worker.js` ; le résultat entre comme une photo déposée (`onImage`).
- Thèmes des hooks, 100 % local : `lib/themes.ts` (lexique promo FR/EN + exemples) et `public/themes/worker.js` (multilingual-e5-small dans le navigateur) → `lib/themeAI.ts`. Priorité : thème mis à la main > modèle > lexique > groupe de mots. Une slide ou les hooks vidéo peuvent tirer dans un seul thème.
- Listes de textes par rôle (`TextPool.kind`) : `hooks` (accroche : slide 1, vidéos), `texts` (les autres slides, transitions…), `captions` (légendes), `block` (ancien, rangé avec les textes). `isLineList` = hooks ou texts (un texte par ligne, thèmes, tirages). Migration unique `textRoles` (flag `textRolesV1`). Le studio vidéo ne montre que hooks et légendes.
- Légendes de post : listes de type `captions` (une case par légende, séparées par `---`), `components/PostCaption.tsx`. Exports : seulement images / MP4 + `caption.txt` ; un carrousel se télécharge en fichiers directs (`saveBlobs`, pas de zip), « tous les carrousels » en un zip (un dossier par carrousel) ; la progression remplit le bouton (`.filling`, `--p`).
- i18n : `lib/fr.ts` (dictionnaire clé = texte anglais). Un test vérifie que chaque `t("…")` a une traduction française : en ajouter une à chaque nouveau texte.
- Menus contextuels maison (`ContextMenu` dans `ui.tsx`, le clic droit du navigateur est coupé par `PointerHabits`, sauf dans les champs) : slide (ordinateur), aperçu vidéo, photo d'une liste (aussi à l'appui long), et un menu global de l'app (racine de `Studio`, quand rien d'autre n'a pris le clic droit). Pas de sélection de texte ni de contour au clic dans l'app. Un `Menu float` dans une pile transformée (pile de slides du téléphone) passe `portal`.
- Outils partagés (ne pas recopier) : `lib/files.ts` (`stamp`, `safeName`, `saveBlob`), `clamp` dans `lib/render.ts`, `sessionEmail()` dans `auth.ts` pour les routes API, `isShareCode` / `SHARE_MINUTES` dans `lib/shareLimits.ts` (client + serveur), `RoleSelect` / `ScopeSelect` dans `ui.tsx`.
- Bibliothèques lourdes chargées au premier usage (`await import(...)`) : JSZip, QRCode, Tesseract, mp4box (`mp4box()` dans `lib/videoSource.ts`), mp4-muxer. Ne pas les réimporter en haut d'un fichier (premier chargement de /studio : 288 ko).
- Sécurité : tout fichier relayé par le serveur (photos trouvées, couvertures TikTok, fichiers du partage) passe par `lib/safeFile.ts` (`fileHeaders` : types limités, pas de SVG, CSP sandbox, nosniff). Un seul partage en cours par compte. Les fichiers du plan B Drive ne sont lisibles par lien que le temps du partage (+5 min), fermés par `closeOpenLinks` (`lib/shareP2P.ts`).

## Design
- Look « éditorial » sombre, sobre, pas de look « SaaS généré par IA ». Accent blanc (le rouge ne sert qu'au danger) ; couleurs en variables CSS dans `app/globals.css` (`--accent`, `--on-accent`, `--danger`, `--video`, `--music`…), jamais en dur.
- Attention aux noms de classes : `.card.sel` = slide sélectionnée (le menu déroulant utilise `.dd`).
- Ne pas animer `filter`/`transform` sur une colonne (ça décale les menus flottants).
- En-tête des studios : chaque contrôle porte une classe `h-*` (`h-gen`, `h-pick`, `h-new`, `h-count`, `h-opts`, `h-share`, `h-dl`, `h-status`) et les conteneurs sont en `display: contents` (`.slot`), pour placer le tout en grille : 2 lignes sur desktop, « Plus » sur mobile (≤ 640 px). Annuler / rétablir et le compte (initiale) sont dans la barre du haut ; sur mobile, le compte est aussi en haut à droite, carrousel en pile à glisser, photo à deux doigts, texte par appui long.
- Sauvegardes d'UI : tags git `ui-video-v1`, `ui-video-v2`, `ui-red-accent`.
