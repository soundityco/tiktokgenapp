# Rollout (anciennement TkTgen) : contexte du projet

Réponds en français. Andy (Angers) construit Rollout avec un ami : une web app pour artistes musicaux qui crée des carrousels TikTok (hooks, paroles, photos Drive) et un studio vidéo (prise caméra synchronisée sur l'audio officiel, paroles incrustées). En ligne : https://getrollout.netlify.app

## Liste des fonctionnalités
- `FONCTIONNALITES.md` : tout ce que fait l'app, du point de vue de l'artiste, par rubrique, avec son état (En ligne, En test, À venir, En attente). À mettre à jour à chaque fonctionnalité ajoutée, changée ou retirée (dans le même commit). Sert aussi pour la home.

## Stack
- Next.js 15 (App Router), TypeScript 5 (ne pas passer à 7 ; pas de `baseUrl` dans tsconfig), Auth.js (next-auth beta) avec login Google + `drive.file` seul (plus de `drive.readonly`, permission restreinte : l'app ne voit que ce qu'elle a créé ; tout s'importe depuis l'appareil). Session JWT d'un an, renouvelée à chaque visite.
- Données : Neon Postgres (table `workspaces`, un JSON par email, compare-and-swap sur `rev`). Sans `DATABASE_URL`, repli sur `.data/workspaces.json` (badge « Local file »). Plusieurs appareils : l'app relit les données au retour sur la page et toutes les 30 s (si rien n'attend d'être enregistré), et un conflit d'enregistrement est fusionné (`lib/merge.ts`, fusion à trois sur la dernière version chargée / enregistrée).
- Déploiement : GitHub + Netlify (`@netlify/plugin-nextjs`, `publish = ".next"` dans netlify.toml, ne pas définir de Base directory). Ne jamais coder le domaine en dur (origine déduite par requête, AUTH_URL dans Netlify).
- Mode démo : `/studio?demo` (connecté) ouvre un compte vierge en mémoire seulement (`lib/demo.ts`) : rien n'est enregistré sur le serveur ni écrit sur le Drive, recharger repart de zéro.
- Tests : `npm test` (vitest, fichiers dans `tests/`). Typecheck : `npm run typecheck`.
- Ne jamais lire ni afficher `.env.local`.

## Architecture utile
- Trois espaces dans les deux studios : **Bibliothèque** (colonne de gauche / onglet du milieu sur mobile : la release — paroles, et pour la vidéo audio + prises — puis les listes de textes partagées, et les photos pour le carrousel), **Création** (board central), **Style** (colonne de droite ; le Cadrage vidéo y est). Les morceaux partagés (`lyricsRow`, `textGroup`) sont construits dans `Studio.tsx` et passés à `VideoStudio`. Sauvegarde avant cette refonte : tag `ui-before-library`.
- `components/Studio.tsx` : carrousel + coquille de l'app (header, release, overlays). `components/VideoStudio.tsx` : studio vidéo, gardé monté (caché) quand on passe au carrousel. `components/SlideCard.tsx` : carte de slide (sources, thème, sections de paroles). `components/Inspector.tsx` : réglages de la slide. `components/CaptionStyle.tsx` : style des paroles / hooks vidéo.
- `components/ui.tsx` : Modal, Menu (option `float` pour sortir d'une colonne), Section (panneaux repliables, fermés par défaut), **Select** (menu déroulant maison : ne jamais utiliser de `<select>` natif).
- `lib/render.ts` : rendu canvas (`drawStyledText`). `lib/types.ts` : modèle de données.
- Médias (audio, vidéo, polices, LUT) : IndexedDB local (`lib/idb.ts`), jamais envoyés au serveur (sauf copie Drive voulue).
- Doublons Drive : `uploadToDrive` réutilise le fichier identique du dossier (MD5, ou nom + taille au-delà de 160 Mo) ; `findDriveTwins` (une fois par jour, `tidyTwins` dans `Studio.tsx`) fusionne les dossiers jumeaux et met à la corbeille les fichiers en double.
- Photos en double dans une liste (même image, fichiers différents) : empreinte visuelle `PicRef.hash` (`lib/imageHash.ts`, 17 × 16 = 256 bits, même photo à ≤ 12 bits) ; calculée à l'ajout (`uploadToList` n'ajoute pas une photo déjà là) et, pour les anciennes, à l'ouverture de la liste (sans étape d'annulation) ; « Retirer les doublons » dans l'éditeur (`dropRepeats`, le fichier Drive à la corbeille s'il ne sert plus).
- Arborescence Drive (`lib/drive.ts`, `DRIVE_PATHS`, `driveFolder`) : `Rollout / Photos / <liste>`, `Rollout / Releases / <release> / Audios, Videos`, `Rollout / Utils / LUTS, Fonts`, créée à la connexion (`ensureDriveTree`) ; chaque envoi va dans son dossier ; une liste de photos ou une release crée son dossier et le renomme avec elle (`renameDriveFolder`) ; les listes de photos se remplissent par glisser-déposer / « Ajouter des photos » (plus de dossiers liés ni d'import depuis le Drive) ; les anciens fichiers à plat dans Rollout sont rangés une fois par appareil (`tidyDriveRoot`). Sauvegarde avant : tag `ui-before-drive-tree`.
- Vidéos et versions : une vidéo = le fichier caméra et ce qui en dépend (synchro, prises, profil caméra de l'étalonnage, objectif anamorphique `desqueeze` : `desqueeze()` dans `lib/videoSource.ts` élargit l'image dans `drawScene`, `cropFor` découpe en pixels caméra) ; une version (`VERSION_KEYS`, « Dupliquer cette version ») garde tous les choix du post (segment, textes, styles, cadrage, format, étalonnage ; les anciennes sans `all` reprennent cadrage / format / étalonnage de la vidéo). « + » = nouvelle vidéo, mêmes réglages, autre fichier ; « Dupliquer » (menu « … ») = même fichier, lu via `media` (jamais recopié sur l'appareil), sans la copie Drive ; on n'efface un fichier local ou une copie Drive que si aucune autre vidéo ne s'en sert.
- Bandes noires (masque à un format, comme DaVinci) : `drawMatte` / `MATTES` dans `lib/render.ts`, `MatteSelect` dans `ui.tsx` ; `SlideCfg.matte` (à la slide, pas à la photo : une autre photo les garde ; copié par « Appliquer à toutes les slides ») et `VideoSettings.matte` (choix de la version)  ; au-dessus de l’image, sous les textes, à l’aperçu comme à l’export ; avec des bandes, l’image n’a qu’à couvrir la partie visible entre elles (`clampPic` lit `pic.matte`, passé au dessin et au glisser, jamais gardé dans la photo).
- Plusieurs carrousels par release : `lib/carousels.ts` (le carrousel ouvert vit dans les champs du projet, les autres dans `project.carousels`).
- Calage des paroles par alignement forcé (sauvegarde avant : tag `before-forced-align`) : `public/align/worker.js` (MMS-300M forced aligner, CC-BY-NC-4.0, onnxruntime-web 1.20.1 : sur carte graphique le modèle fp32 de onnx-community, 1,26 Go, cache `rollout-align-fp32` ; sur processeur (wasm) le fp16 de tatsu020, 630 Mo, cache `rollout-align`, ~2 min pour 80 s d'audio. Ne JAMAIS passer le fp16 sur WebGPU : il y donne des valeurs fausses sur certains morceaux (mesuré dans Chrome contre la référence processeur) ; l'int8 et le q4 ne marchent pas ou sont trop lents en wasm ; extraits de 30 s avec 2 s de contexte, log-probabilités par image de 20 ms) → `lib/alignAI.ts` (`alignEmissions`, garde la dernière chanson en mémoire) → `lib/forcedAlign.ts` (`alignWordsForced` : chemin CTC de Viterbi sur les lettres a-z + apostrophe, `faNorm`, ~50 ms ; les mots d'une ligne éloignés de plus de 4 s du reste sont recalés près d'elle, `strayBounds` ; `LyricWord.doubt` = ligne douteuse (éparpillée, ou tassée au-delà de 26 lettres/s jusqu'à la ligne suivante : seuil mesuré sur 3 chansons, la confiance des lettres ne discrimine pas), point jaune `.cue-doubt` dans les lignes de paroles, ôté quand la ligne est retouchée `manual` ; `LyricWord.exact` : ne PAS passer ces mots par `tightenLineStarts` / `snapLines` dans `placeWords` (ça reculait une ligne de 1,1 s) ; le dernier mot d'une ligne dure au plus 1 s (`HOLD`) ; un blanc à l'intérieur d'une ligne coûte `FA_TUNE.lineBlank` = 0,05 ; paroles françaises (`looksFrench`) alignées sur une graphie phonétique (`frenchSound` : « en » → « an », finales muettes ôtées, « est » → « e » : le modèle écrit ce qu'il entend, « comprends » = « compran ») et lettres de début de ligne jamais entendues (< 3 %, une syllabe avalée : « Qu'est-ce qui » chanté « s'qui ») recollées devant la première entendue (`startOnHeard`). Relais (`lib/lyricsRelay.ts`, `relayWeakLines`) : un passage presque muet pour l'alignement (lignes `weak` : moyenne de leurs lettres < 0,3 sur un passage dont la moyenne < 0,12, dont certaines `doubt`, tassées ; un hook ou un refrain noyé dans les effets) est réécouté par Whisper en mode phrase (`transcribe(…, { mode: "segment", raw: true })`) ; les lignes du passage sont alignées (`alignSong`) sur les mots de ces phrases (une phrase peut porter plusieurs lignes : un bloc de refrain) ; une ligne non tassée garde son heure si l'écart ≤ 1 s ; une ligne avec une lettre nettement entendue (> 0,6) n'est jamais `weak`. Whisper reçoit en amorce les lignes chantées juste avant (`prompt` → `decoder_input_ids` = <|startofprev|> texte <|startoftranscript|><|fr|><|transcribe|>, écho retiré de la 1re phrase) : sans elle il rendait « ... » / « Sous-titrage » sur presque toutes les fenêtres du hook de WANNA TRY (une seconde de décalage suffisait à basculer) ; amorcer avec TOUTES les paroles le fait recopier et boucler. Fenêtre sans parole (`noSpeech`) : réessayée décalée. Le relais écoute en mode mot ET phrase (amorcés) : les mots (plus fins, `withoutLost` retire ceux empilés au même instant) là où il y en a, les mots des phrases ailleurs (`mergeHeard` : le mode mot s'arrête parfois au 1er bloc d'un refrain) ; un 1er mot de ligne qui dure > 0,6 s jusqu'au suivant a absorbé le blanc avant lui (coupure dans la prod) : recalé 0,25 s avant le mot suivant (`FIRST_LONG`). Essais écartés (mesurés) : répartir les lignes non entendues sans Whisper (Ally Bakst 0,11 → 5 s), zones de surdité ≥ 4 s, seuil par ligne seul (le rap rapide est à moitié entendu, DAKEEZ 85 → 72 %). Mesurer TOUJOURS avec l'audio préparé comme l'app (décodé par le navigateur, OfflineAudioContext 16 kHz) : ffmpeg donnait d'autres émissions et un réglage qui ne tenait pas dans l'app ; une coupure de ligne qui ne suit pas le chant (« …partir dans / tes draps ») fait commencer la ligne sur le mot chanté avant, ce n'est pas une erreur, jamais dans la ligne suivante ; vérité terrain de WANNA TRY V4 mesurée sur l'acapella : attaques de voix à 35,25 / 38,5 / 42,5 / 46,75 s, Whisper y donnait 36,5 / 40,8… à tort) ; les mots posés deviennent `project.heardWords`, donc la resynchro au changement de texte, les versions audio et les retouches marchent comme avant. Utilisé quand les paroles sont écrites (`src` « song » / « all ») ; sinon, ou en cas d'échec, Whisper (voir ci-dessous). Mesuré hors app contre LRCLIB sur 6 chansons FR/EN : médiane 0,05–0,46 s, refrains serrés (« Air, air », « Non ×4 ») encore fragiles. Whisper : si les temps par mot s'effondrent (tous au même instant : `lostCount`), la fenêtre est réécoutée en temps par phrase (`wordsFromSegments`, mode `segment` du worker), `respreadLost`, et `dropLoops` garde une répétition présente dans les paroles écrites.
- Paroles : un seul texte par release, les sections `project.lyrics` (`lib/lyricsSections.ts` : découpage d'une chanson, slides en paroles, lien avec la vidéo via `songOf`/`lyricsLinked`, migrations au chargement). Éditeur unique `components/LyricsEditor.tsx` (tuile Paroles en tête de la Bibliothèque des deux studios, couleur or ; l'audio en vert, la vidéo en violet). Une slide retouchée à la main (`edited`) ne suit plus les sections.
- Copie de travail des prises (autres appareils) : après la synchro, d'abord `fastWorkCopy` (`lib/fastCopy.ts`, puce vidéo via WebCodecs : H.264 en 8 bits, HEVC Main 10 ou VP9 profil 2 en 10 bits, son lu par ffmpeg), sinon `makeWorkCopy` (`lib/convert.ts`, moteur ffmpeg à part) encode le passage ±2 s en gardant le minutage de l'original (image figée avant, son caméra), 10 bits 4:2:2/4:2:0 pour log/HDR/10 bits/ProRes, 8 bits pour le SDR, ≤ 1920 px ; envoyée sur le Drive (`drive.copy`). L'index lu par mp4box (`readIndex`, copie et export) ne garde que les pistes vidéo (`videoOnlyMoov`) : le son PCM d'une prise XAVC = un objet par échantillon, des Go, la page plantait (« Aw, Snap! » 15 s après le chargement). Sans le fichier caméra, l'app ouvre la copie (`copy:<clip>` en local, pastille « Copie Drive ») ; l'appareil qui a l'original exporte depuis l'original.
- Réglages d'export recommandés pour TikTok / Instagram (`recommendedRate` dans `lib/exportVideo.ts`) : la cadence de la prise (`VideoSourceInfo.fps`, lue par `lib/probe.ts` : note Sony `formatFps`, sinon `stts`/`mdhd` de la piste vidéo ; inconnue : 30), 16 Mb/s jusqu'à 30 i/s puis autant de bits par image au-delà, plafonné à 24 Mb/s (Instagram recompresse plus fort au-delà de 25), niveau H.264 4.2 au-dessus de 30 i/s, image clé toutes les 2 s ; son AAC 256 kb/s en stéréo (160 en mono, moins si le navigateur refuse), 48 kHz au plus (`exportSampleRate`, ré-échantillonné par `OfflineAudioContext`). Ne pas monter au-delà ; HDR, HEVC et 4K déconseillés. Le grain de l'étalonnage garde son rythme (`GRAIN_FPS`). Réglages perso du compte : `Workspace.videoExport` (`VideoExportPrefs`, `custom` + cadence / Mb/s / kb/s), appliqués par `exportSettings` ; rubrique « Export » (`#video-export`, même structure que Couleur : titre, (i), interrupteur « Modifier ») en bas de la colonne de droite du studio vidéo, onglet Export de la page Style sur téléphone.
- Étalonnage, ordre de la chaîne (`buildGradeLut`, une LUT 3D pour l'aperçu et les deux exports) : log caméra → DWG linéaire → exposition et balance des blancs → DaVinci Intermediate → contraste → roues (`VideoGrade.wheels`, offset / lift / gamma / gain, `WHEEL_RANGE`, point de couleur sur les axes d'un vectorscope `wheelRgb`) → saturation → sortie : Rec.709 de l'app, ou une LUT réglée comme un CST avant elle (`LutRef.input` : log de la caméra de la vidéo — S-Log3 en code/1023, `INPUT[].lutIn` —, DWG/Intermediate, Rec.709/Cineon Film Log (`linToCineon`), Rec.709/gamma 2.4 ; `output` « display » = image finale ou « same » = l'app convertit en Rec.709 après ; `tonemap` = hautes lumières adoucies (`easeHighlights`, proche du CST de DaVinci, pas identique) ; entrée devinée à l'import par `guessLutInput` ; anciens `kind` lus par `lutInputOf`). Ces réglages sont ceux de la vidéo (dans sa prise) : une autre vidéo peut utiliser la même LUT autrement ; la bibliothèque ne garde que la valeur de départ d'une nouvelle vidéo (`withLutSettings` ne la prend que si la vidéo n'a pas les siens ; migration unique `lutPerVideo` / `lutPerVideoV1` dans `lib/defaults.ts`) ; vignettage et grain après. Sauvegarde avant : tag `before-lut-cst`. Roues : `components/ColorWheels.tsx` (panneau « Roues », façon Final Cut). Effets (panneau « Effets » entre Roues et Finition, `VideoGrade.mist`/`haze`…, `bypass.effects`) : `lib/effectsGL.ts` (WebGL 2 : Black Mist qui déplace la lumière sans en ajouter, Halation à part, Brume ; flous en basse résolution lus dans les mipmaps de l'image, sinon l'image scintille ; chaque passe hors écran garde le sens des textures, uniform `screen`), appliqués par `drawLook` avant vignettage et grain, donc aperçu, export et pellicule ; sauvegarde avant : tag `before-mist-haze` ; la Brume avec carte de profondeur (IA) est à faire. Interrupteurs : celui de Couleur coupe tout l'étalonnage, aperçu et export (`VideoGrade.off`, `gradesColour` faux, panneaux grisés `.cg-parts.off`) ; ceux de Corrections, Roues et Finition coupent leur étage, réglages gardés (`VideoGrade.bypass`, `effectiveGrade` dans `lib/grade.ts`). L'« Avant / Après » sous l'aperçu reste la comparaison (`rawView`, aperçu seulement). Sauvegarde avant : tag `before-color-wheels`.
- Presets de couleur : `Workspace.gradePresets` (`GradePreset`), panneau « Presets de couleur » en tête de Couleur (`GradePresets` dans `components/ColorGrade.tsx`, comme les presets de texte) ; un preset garde tout l'étalonnage (profil caméra, LUT de sortie avec sa copie Drive, réglages, roues) ; a remplacé « Appliquer à d'autres vidéos ». Bibliothèque de LUT du compte : `Workspace.luts` (`LutRef`, visible sur tous les appareils et adresses de l'app) ; une LUT importée y entre et part aussitôt sur le Drive (Utils / LUTS, `lutSent` dans `VideoStudio`) ; les LUT connues du seul navigateur (`knownLuts`, localStorage) la rejoignent ; une LUT absente de l'appareil est récupérée par sa copie Drive. Une même LUT en double (même nom et type, `sameLut`) est fusionnée au chargement (vidéos et presets repointés sur celle qui a sa copie Drive, `Studio.tsx`) ; réimporter une LUT du même nom et type remplace son entrée ; corbeille au survol dans le menu Sortie (`Select` : `onRemove`), confirmée, retire la LUT du compte, des vidéos et des presets (`askRemoveLut`).
- Export vidéo étalonné (log / LUT) : d'abord `gpuGradedSource` (`lib/grade10.ts` : images décodées par WebCodecs en logiciel, plans Y/Cb/Cr 10 bits lus avec `copyTo`, BT.709 + LUT 65 tétraédrique dans un shader WebGL 2, comme ffmpeg), sinon `convertSegment` ffmpeg. Les images matérielles sans format lisible (HEVC sur Chrome Mac ou Android, la copie Drive sur téléphone) sont déposées sur le GPU par le navigateur (`drawRGB` : RGBA16F si possible, sinon 8 bits) puis étalonnées par la même LUT ; ffmpeg seulement si ça échoue aussi. Sauvegarde avant : tag `export-before-gpu-grade`.
- Prises (sauvegarde avant : tag `before-takes`) : une prise importée = une `VideoSetup` marquée `takeOnly` (pas un projet : hors du sélecteur « Projet », `projects` dans `VideoStudio`) ; `importTakes` (plusieurs fichiers, `video:<id>` en local, les premières en caméras du projet), `prepareTake` (`probeVideo`, `gradeForSource`, `readSound` puis `syncAudio`, en arrière-plan, `takeJobs`) ; Bibliothèque : « Prises du projet » (carte de la caméra 1 toujours ouverte, `clip-card cam-0`, lignes `take-row` des caméras 2 à 4, `takesEl`), « Autres prises de la release » repliée. Copie Drive des prises : `makeCopy(take)` (même file d'attente que la caméra 1), planifiée pour les caméras du projet ; une prise absente de l'appareil est lue depuis sa copie Drive (`Angle.fromCopy`). Lignes et cartes : `card()` dans `takesEl`, `sourceNote`, `takeCopyEl`, transition de hauteur (`foldTo` + `useLayoutEffect`, classe `takes-branch`).
- Multicam (sauvegarde avant : tag `before-multicam`) : `VideoSettings.angles` (ids d'autres vidéos de la release, caméras 2 à 4, même version d'audio) et `cuts` (`lib/multicam.ts` : `camAt`, `cutTo`, `setShotCam`, `splitAt`, `removeCutAt`, `moveCut`, `shotsOf`) ; dans `VideoStudio`, `anglesRef` (lecteur caché par caméra, fichier `video:<media>` sinon `copy:<clip>`, sa LUT 33), `drawScene(..., angle)` prend le cadrage et l'étalonnage de la caméra, `syncAngles` ne fait jouer que la caméra à l'écran ; à l'export, chaque caméra est ouverte à son premier plan (`gpuGradedSource` si étalonnage, sinon `VideoSource`, sinon son lecteur) ; touches 1–4, C, Suppr ; piste `cam-track` sous les paroles. La colonne de droite règle la caméra de l'aperçu (`pinCam` épinglée depuis la bibliothèque, sinon le plan sous la tête de lecture ; `camTake`, `writeLook`, `panelGrade`, `curFrame`) ; `lutFile` charge une LUT (appareil, jumelle, Drive) pour la caméra 1 comme pour les autres.
- Versions de l'audio d'une release (démo, master, sped up…), par vidéo : `lib/audioVersions.ts`. L'audio principal reste dans les champs du projet (`audioName`, `lyricWords`…, fichier local `audio:project:<id>`), les autres dans `Project.audios` (mêmes champs, fichier `audio:<id>`), chaque vidéo sur `VideoSettings.audioId` (sans : le principal). `VideoStudio` travaille sur `projectFor(release, audioId)` (la vue de la version de la vidéo ouverte) et réécrit avec `writeFor`. Ajouter un audio quand il y en a un = une nouvelle version (« Cette vidéo / Toutes / Aucune ») ; changer de version (tuile Audio) recale la vidéo : `alignTracks` (`lib/syncAudio.ts`, extraits de 4 s, chemin de Viterbi, gain relatif) puis `lib/audioRemap.ts` (`trackMap`, `mapSpan`, `remapClip`, `remapWords`) ; compte rendu par vidéo (inchangée, recalée, à vérifier, passage disparu). Tests : `tests/audioRemap.test.ts`, `tests/audioVersions.test.ts` (chansons de synthèse : `tests/songSim.ts`).
- Synchro audio caméra ↔ officiel : `lib/syncAudio.ts` (le score = certitude de la position : extraits d'accord + écart avec les autres endroits ; la ressemblance du son ne compte qu'au-dessus d'un seuil bas, pour une voix seule au casque). Son de la caméra : décodé par le navigateur jusqu'à 400 Mo, sinon ffmpeg (piste son seule, secondes), en dernier recours capture en temps réel. Pendant la lecture, la copie de travail (puce vidéo) attend ; sa progression ne redessine le studio qu'à chaque pour cent ; le MD5 d'un envoi Drive se calcule par tranches (`md5Blob`). Paroles calées sur l'audio : `public/asr/worker.js` (Whisper via transformers.js 3.7.6 sur jsDelivr ; carte graphique WebGPU si elle marche — encodeur fp32, décodeur q4 —, sinon processeur wasm q8, repli automatique ; « Très précis » = Whisper large-v3-turbo_timestamped, q4f16 si la carte calcule en demi-flottants sinon q4, environ 560 Mo une fois, carte graphique seulement, par défaut quand `hasGpu()` : sur « MENSONGES », 82 mots justes en 28 s là où « base » entendait du charabia ; sinon « base ») → `lib/transcribe.ts` (`prepareAudio` : mono = centre du mix, filtré 110 Hz – 7 kHz) → `lib/lyricsAlign.ts` (`cleanHeard` : `joinPieces` recolle les mots coupés aux apostrophes / traits d'union par le modèle très précis — « c » + « 'est » —, sans quoi les couplets pleins d'élisions ne se calaient pas ; `dropMadeUp` retire « Sous-titrage Société Radio-Canada » & co ; les mots horodatés hors de la fenêtre écoutée sont écartés ; `dropLoops` : Whisper répète des phrases en boucle sur la musique, 1 225 mots entendus dont 156 réels ; `spreadOnHeard` en dernier recours ; `placeMissed` : seuls les mots non reconnus de la ligne du prochain mot entendu sont collés avant lui, les autres lignes non entendues suivent la phrase d'avant ; `tightenLineStarts` : le premier mot d'une ligne raccroché à la pause d'avant revient avant sa ligne). Une fenêtre qui rend moins d'un mot toutes les 4 s est réécoutée en deux moitiés (Whisper perd parfois 28 s entières : le refrain 2 de MENSONGES). Banc d'essai : MENSONGES V2 + ses paroles, 66 % des mots reconnus, chaque ligne au bon moment. Jonction : `joinCue` (les mots de la ligne suivante prennent sa ligne et `glue` : ni pause ni longueur ne les recoupent, `phrasesOf`), puis `splitCue` au bon endroit. Retouches : `moveCueStart` (début d'une ligne glissé sur la piste, `cue-edge`, la ligne d'avant suit, Alt = seule) ; `retimeCue` « start » + sur une ligne collée à la suivante passe par `moveCueStart` ; hooks glissés de même (`moveHook`) ; poignées de fin (`moveCueEnd` = le + / − de fin, `moveHookEnd`) seulement là où une ligne est suivie d'un vide ou est la dernière (une frontière collée a déjà la poignée de début). Attaques de la voix (`lib/voiceOnsets.ts`, `snapLines`) seulement sur un mix aéré ; sur un mix dense (une attaque toutes les 0,4 s : la batterie) aucune. Calage trop faible : nouvelle écoute par « small », puis paroles posées à peu près sur le chant, avec un message. Les mots sont dans `project.lyricWords` (temps absolus, `manual` = retouche gardée au recalage).
- Tags des textes (plusieurs par texte) : `TextPool.tags` (posés à la main), sinon le thème trouvé sert de tag (`poolTags`, `tagGroups`, `taggedItems` dans `lib/generate.ts`) ; une slide (`textSource.tags`) ou les hooks vidéo (`hookTags`) tirent dans les tags cochés (un texte qui en a au moins un). ## Design
- Look « éditorial » sombre, sobre, pas de look « SaaS généré par IA ». Accent blanc (le rouge ne sert qu'au danger) ; couleurs en variables CSS dans `app/globals.css` (`--accent`, `--on-accent`, `--danger`, `--video`, `--music`…), jamais en dur.
- Attention aux noms de classes : `.card.sel` = slide sélectionnée (le menu déroulant utilise `.dd`).
- Ne pas animer `filter`/`transform` sur une colonne (ça décale les menus flottants).
- En-tête des studios : chaque contrôle porte une classe `h-*` (`h-gen`, `h-pick`, `h-new`, `h-count`, `h-opts`, `h-share`, `h-dl`, `h-status`) et les conteneurs sont en `display: contents` (`.slot`), pour placer le tout en grille : 2 lignes sur desktop, « Plus » sur mobile (≤ 640 px). Annuler / rétablir et le compte (initiale) sont dans la barre du haut ; sur mobile, le compte est aussi en haut à droite, carrousel en pile à glisser, photo à deux doigts, texte par appui long.
- Sauvegardes d'UI : tags git `ui-video-v1`, `ui-video-v2`, `ui-red-accent`.
